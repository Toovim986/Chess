# Шахматы VK Play

Текущая сдача — скриншоты шести мобильных экранов по ГДД, собранных из экземпляров ♦️ Poker lib, и карты передачи во фронт по эталону «Новости». Прежние PNG-концепты главной сохранены как родительская ревизия.

## Быстрый старт

Нужен Node.js 20+ (Python 3.10+ — только для тестов движка). Зависимостей ставить не нужно: `npm install` не требуется.

```powershell
git clone https://github.com/Toovim986/Chess.git
cd Chess
npm.cmd start   # Windows; на macOS/Linux — npm start
```

Открыть <http://127.0.0.1:43132/>. `npm run preflight` вернёт код 2 (открытые решения) — это штатно, не поломка.

Не входят в репозиторий (слишком тяжёлые): исходники и данные профиля Poker (`tools/design-verifier/profiles/poker/{source-repository,data,snapshots}`), сырые входные данные `profiles/*/incoming`, старые аудиты и итерации экранов v3–v6.

## Просмотр экранов

## Границы текущего результата

Экраны новой поставки собраны из проверяемых экземпляров Poker lib: вне экземпляров нет ни одного цвета, не привязанного к переменной. Переходы, состояния поиска и ошибок, viewport-политика и данные из реального приложения не покрыты, поэтому готовность к вёрстке остаётся `INCOMPLETE`. Значения на экранах демонстрационные. Прежние растровые концепты главной не содержат экземпляров DS.

Движок проверяет часть геометрии и свойств, но исключает привязки переменных и не сравнивает всю типографику. Импортированный отчёт хранит результаты его автора. Полный автоматический контроль применения DS ещё требует доработки.

Архивные проверки самого инструмента в этой сессии: 29 JavaScript-тестов и 17 Python-тестов PASS. Это не одобрение дизайна новых экранов. Результат начального копирования с SHA-256 каждого файла — `integration/verifier-copy.json`.

## Дальнейшая работа

Согласовать экраны и карты; закрыть пробелы DS у владельца Poker lib; утвердить viewport-политику и место сдачи (`destination` в профиле Chess). Затем перенести утверждённые экраны из рабочего файла в «Шахматы» как редактируемые макеты и собрать недостающие состояния новой ревизией.

Вкладка [«Карта экранов»](http://127.0.0.1:43132/?view=screen-map) показывает 12 существующих концептов Chess, варианты главной, предложенные переходы, недостающие состояния и реальные источники компонентов. Данные: `tools/design-verifier/verifier/public/screen-map/chess.json`; план компонентов: `design-system/chess-component-plan.json`. Покерный пример сохранён как исторический материал и в профиле Chess не показывается.

По указанию пользователя максимально переиспользуем готовые компоненты DS: кнопки, аватары, карточки, типографику, иконки и токены. Имеющиеся элементы не перерисовываем генератором. Когда готового шахматного элемента нет, фиксируем конкретный пробел. Библиотечные экспорты во вкладке карты — реальные исходные образцы, а не доказательство их внедрения в прежние PNG.
