# Подключение следующей игры

В рабочем проекте достаточно одной инструкции с указанием отдельного инструмента:

```text
Перед сборкой или проверкой макетов прочитай
D:/Porfiriy/Projects/Work/Верификатор/AGENTS.md
и выполни из этой папки: node cli.mjs context chess.
Применяй правила только в указанном scope и проверь текущие источники через Figma.
После работы сохрани ревизию с доказательствами в профиле этой игры.
```

Для новой игры сначала создать отдельную папку `profiles/<id>/` с `project.json` и `runtime.json` по образцу Chess. Указать собственные название, surface, порт, источники сценариев, композиционный контракт и страницу сдачи. Общая DS может ссылаться на тот же `design-systems/poker-library/source.json`, но применимые компоненты и варианты проверяются для новой задачи.

Затем выполнить `node cli.mjs preflight <id>`, разобрать перечисленные пробелы и начать с одного утверждённого сценария. База Chess намеренно содержит незакрытые продуктовые и композиционные вопросы; их нужно разрешить для конкретной игры.

Все будущие проекты ссылаются на одну установленную папку Верификатора. Для совместного использования несколькими людьми потребуется отдельно выбрать версионируемое хранилище и способ распространения: эта версия локальная, не командный сервер.
