# Верификатор игровых интерфейсов

Общий инструмент для подготовки контекста, проверки измеримых свойств и хранения доказательств дизайна. Версия 0.1.0 извлечена из Poker 27.10.2026. Работает из собственной папки; исходный Poker для запуска не нужен.

Начните с `docs/assessment.md`: там выводы аудита, рекомендуемые решения и границы текущей реализации. Договор работы агента — `AGENTS.md`, практический цикл — `docs/workflow.md`.

## Запуск

Нужны Node.js 20+ и Python 3.10+. Сетевые зависимости для сервера и Python-движка отсутствуют.

```powershell
cd 'D:\Porfiriy\Projects\Work\Верификатор'
node cli.mjs serve chess
```

Открыть <http://127.0.0.1:43130>. История Poker запускается отдельно: `node cli.mjs serve poker`, адрес <http://127.0.0.1:43131>. Профили имеют собственные `data/` и `incoming/`. Контракт HTTP-импорта описан в `RUNTIME.md`.

```powershell
node cli.mjs context chess
node cli.mjs preflight chess
node cli.mjs search chess перекры
node cli.mjs history poker
npm.cmd test
python -B -m unittest discover -s engine -p 'test_*.py'
```

`context` возвращает правила, источники, пробелы, уроки и порядок работы. Его читает агент перед сборкой. `preflight` проверяет наличие и целостность локальных доказательств конфигурации: exit 2 = INCOMPLETE, exit 0 = READY_FOR_REVIEW, а не одобрение макетов. Содержательная проверка источников выполняется отдельно через Figma.

## Что находится в папке

- `verifier/` — локальный пульт, API, импорт ревизий и журнал; `engine/` — проверки исходника и сетки, сборщик Figma-снимков.
- `knowledge/` — правила процесса и уроки. Статус `candidate` означает, что правило требует решения перед применением.
- `profiles/chess/` — отдельный профиль mobile-first. DS подключена по ссылке пользователя; сценарии, композиция, viewport и место сдачи пока не определены.
- `profiles/poker/data/` — побайтная копия накопленного архива, включая исходные FAIL/INCOMPLETE.
- `profiles/poker/source-repository/` — снимок исходных документов и кода Poker с сохранением относительных путей. Это исторический материал, не действующие инструкции шахмат.
- `migration/manifest.json` и `migration/verification.json` — список перенесённых файлов, SHA-256, охват и результат независимого перечитывания. `docs/validation.md` — выполненные проверки.

История Poker в этой папке — снимок на момент переноса. Две копии Poker не синхронизируются автоматически; существующий пульт в исходном проекте сохранён.

В `profiles/chess/project.json` фиксируются источники с версиями, локальными доказательствами и SHA-256; технический профиль пульта расположен в `runtime.json`.

Сборку Figma выполняет агент или дизайнер, используя этот контекст и Figma MCP. В этой версии отсутствуют автоматическая синхронизация DS, автоматическая сборка экранов, полный аудит токенов/типографики и runtime-тестирование игр. Положительный результат сохранения пакета не меняет статус его дизайна.
